## 1. Что сейчас особенно хорошо работает

### Живые ответы
Бот говорит от первого лица, как консультант, а не как система. Ответы собраны вокруг **вопроса человека**, а не вокруг «что интересного в карте». Появилось ощущение диалога, а не выгрузки отчёта.

### Астрология внутри повествования
Астрология **вплетена** в текст: сначала смысл и жизненное проявление, потом компактная опора в ✦. Нет режима «сначала энциклопедия знаков и аспектов, потом вывод в две строки».

### Доказательная база через ✦
Блок ✦ стал **проверяемым**: факты из профиля, орбы, привязка к линиям ответа. Пользователь видит, *на чём* стоит интерпретация, без смешения жизненных абзацев и астро-фактов в одной каше.

### Меньше пафоса
Убраны (или сильно ослаблены) автоматические формулировки уровня судьба, предназначение, кармическая пара, «буквально связаны», «главный ориентир жизни» без наблюдаемого слоя. Тон уверенный, но без театра и без гарантий «да/нет».

### Наблюдаемость и практический смысл
В ответе обязательна цепочка: **сигнал карты → что обычно наблюдают → практический смысл** («часто / может»). Появилось узнавание: человек чаще кивает «да, похоже», а не только «красиво написано».

### Follow-up chips продолжают диалог
После завершённого ответа — до 4 чипов в стиле приложения; при хвостике-приглашении — «Да, расскажи подробнее». Тап сразу отправляет вопрос. Чипы **расширяют** тему, с дедупликацией по смысловому `intentId`, чтобы не возвращать уже открытые ветки.

## 2. Что нельзя потерять

Ниже — не «пожелания», а **инварианты**, которые дали текущий баланс. Любое изменение, которое их ломает, требует явного согласования и теста до/после.

| Инвариант | Почему критично |
|-----------|-----------------|
| **Естественное вплетение астрологии** | Термины и факты служат смыслу, а не заменяют ответ |
| **Баланс карта ↔ жизнь** | Карта — источник истины; вопрос — направление отбора; жизнь — в основной части |
| **Структура: основной ответ → ✦** | Читаемость и доверие; ✦ не дублирует простыню интерпретации |
| **Нет справочника аспектов** | Запрет каталога дигнитетов и перечисления «всего сильного» без связи с вопросом |
| **Нет психологической отсебятины без карты** | Коучинг и «поддержка» не подменяют астрологический разбор |
| **Нет лишнего пафоса** | Судьба / карма / предназначение — только с наблюдаемым слоем или не использовать |
| **Визуальный стиль чипов** | `chat-quick-prompt-chip`: золотая pill, полная ширина под ответом; affirm чуть выделен — без заголовка «Продолжить тему» |

Дополнительно сохранить:

- **1–3 линии синтеза** на обычный вопрос (не «вся карта в одном сообщении»).
- **Опциональный крючок** в тексте — только при реально новом слое, без фальшивого «есть ещё один момент».
- **Иерархию методов** (натал → прогрессии/дирекции → соляр → транзиты) при глубоких вопросах.
- **Честность** при поправке пользователя и при бинарных прогнозах (вероятности, не оракул).

## 3. Почему версия ощущается сильной

### Не генератор отчётов, а консультант
Продукт перестал ощущаться как «GPT + астрологический словарь». Появился голос: короткие заголовки линий, бытовые формулировки (ANTI-GPT-SPEAK), ответ на скрытый запрос (деньги → безопасность, отношения → триггер).

### Хочется продолжать разговор
Текстовые хвостики (когда уместны) + follow-up chips снижают трение: не нужно придумывать следующий вопрос с нуля. Dialog state (`usedSignals`, `lastHookTopic`) помогает не зацикливаться на одних транзитах.

### Чипы помогают сформулировать вопрос
Чип — это готовая **жизненная** формулировка («что делать с напряжением?», «когда вероятна встреча?»), не астрожаргон. Это мост между эмоцией пользователя и структурой консультации.

### Ощущение «меня поняли»
Срабатывает связка наблюдаемого слоя + ответа на реальный вопрос, а не на «что в карте сильное». Меньше ощущения, что бот «читает лекцию по наталу».

### Астрология видна, но не давит
✦ даёт прозрачность для тех, кому важна опора. Основной текст остаётся для человека, который читает как разговор. Ни то, ни другое не должно доминировать в ущерб другому.

## 4. Какие зоны не трогать без отдельной проверки

Перед изменением — **read-only аудит**, согласование (см. D-012), тесты на 5–10 реальных диалогов, сравнение с [`SNAPSHOT_2026_06_03.md`](./snapshots/SNAPSHOT_2026_06_03.md).

| Зона | Файл / область |
|------|----------------|
| **Основной промпт ответа** | `artifacts/api-server/src/routes/openai/conversations.ts` → `buildSystemPrompt()` |
| **Стиль и тональность** | Блоки «Как ты думаешь», «Как ты отвечаешь», тревожные запросы, ANTI-GPT-SPEAK |
| **Порядок блоков** | Сначала основная часть, потом ✦ (не наоборот) |
| **✦-формат** | Компактные строки, факт → зачем для линии; без коучинга в ✦ |
| **Режимы общения** | Отдельные UI-режимы «лёгкий/глубокий» не внедрялись — риск регрессии |
| **Генерация основного ответа** | Temperature 0.2, SSE, стриминг, без второго прохода «переписать ответ» |
| **UI чата в целом** | `Chat.tsx`, `AstroMarkdown`, composer, PeoplePanel, режим контакта |

**Исключение:** точечные багфиксы (стриминг, z-index, 413) — можно, если не меняют поведение текста.

## 5. Что можно улучшать осторожно

Эти области **не ломают** текущий баланс, если менять маленькими шагами и мерить результат.

| Область | Как улучшать безопасно |
|---------|-------------------------|
| **Дедупликация follow-up chips** | Уже есть `intentId`; можно уточнять regex и пулы, не трогая промпт ответа |
| **Туториал** | Подсказки под chips, режим контакта, ✦-блок — только UI-копирайт |
| **Пустой экран личного диалога** | Копирайт и стартовые темы; не менять `buildSystemPrompt` |
| **Контекстные follow-up chips** | Генерация из ответа (отдельный лёгкий вызов), **не** смешивать с основным промптом |
| **Сбор тестов «до/после»** | 10–15 эталонных вопросов + чеклист из раздела 1 этого файла |

Не делать «в одном PR»:

- переписывание промпта + новые режимы общения + смена ✦-формата;
- подключение `tonePreferredDepth` в промпт без A/B;
- обязательный крючок в каждом ответе (откат к клиффхэнгеру).

## Как пользоваться этим документом

1. **Перед крупной доработкой** — прочитать разделы 2 и 4.
2. **После доработки** — прогнать эталонные диалоги; если пропало что-то из раздела 1 — откат или доработка diff.
3. **Для отката поведения чата** — `git checkout 4f77f62 -- artifacts/api-server/src/routes/openai/conversations.ts` (и связанный UI, если нужно).
4. **Для полного снимка** — [`docs/snapshots/SNAPSHOT_2026_06_03.md`](./snapshots/SNAPSHOT_2026_06_03.md).

## Краткая формула удачной версии

> **Живой консультант:** ответ на вопрос → наблюдение → смысл → ✦ как доказательство → по желанию хвостик и chips для следующего шага — без справочника, без пафоса, без психологии вместо карты.

Если следующая итерация не проходит эту формулу на тестовых диалогах — считать регрессией, пока не доказано обратное.
