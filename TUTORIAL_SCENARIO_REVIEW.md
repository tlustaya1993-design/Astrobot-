## Общий вывод

Нарратив правильный — логика «стартуй → углубляй → добавь людей → синастрия → режим → лимиты → регистрация» соответствует пути пользователя. Из 7 шагов **5 имеют технические конфликты** с текущей архитектурой dev. Ни один не блокирует реализацию намертво, но каждый требует осознанного решения перед внедрением.

---

## Шаг 1 — Задай вопрос или выбери готовый вариант

**Проблема: два target в одном шаге.**

Архитектура `TutorialOverlay` поддерживает ровно один `targetId` на шаг — одну spotlight-подсветку. Подсветить одновременно `chat-input` и `quick-topics` (`ChatQuickPromptSlider`) нельзя.

**Решение:** добавить обёрточный `<div data-tutorial-id="composer-area">`, который объединяет слайдер и инпут. Оба элемента соседствуют вертикально в одном dock — совместный bbox будет аккуратным.

**Статус: реализуемо, нужна правка разметки.**

---

## Шаг 2 — Продолжай разговор (FollowUpChips)

**Проблема: элемент не существует при старте туториала.**

`FollowUpChips` рендерится только при условии:
```
lastFollowUp.chips.length > 0 && msg.id === lastFollowUp.messageId
```
На пустом чате (туториал стартует именно там) — сообщений нет → chips нет → элемент не в DOM.

Дополнительно: у компонента атрибут `data-testid="follow-up-chips"`, а не `data-tutorial-id` — spotlight его не найдёт в любом случае.

**Варианты:**

- **A) Centered fallback** — шаг без spotlight, тултип по центру экрана. Текст работает концептуально («после каждого ответа появятся...»), пользователь поймёт проспективно.
- **B)** Перенести шаг на после первого ответа — архитектурно сложно, туториал сейчас не умеет ждать событий.
- **C)** Добавить `data-tutorial-id="follow-up-chips"` + принять вариант A как стандарт для этого шага.

**Статус: критический конфликт. Рекомендуется вариант A — принять centered fallback как осознанный выбор.**

## Шаг 3 — Добавляй близких людей

**Всё ок.** `data-tutorial-id="people-panel"` существует в `PeoplePanel.tsx:105`, рендерится всегда. Spotlight сработает.

**Статус: ✅ работает без изменений.**

---

## Шаг 4 — Смотри отношения через две карты

**Проблема: целевой элемент не существует без выбранного контакта.**

`ContactAnalysisModeScreen` рендерится при: `selectedContactId != null && displayMessages.length === 0`  
`ContactHeaderModeSwitch` рендерится при: `selectedContactId != null && displayMessages.length > 0`

На старте туториала `selectedContactId = null` → ни одного из этих элементов нет в DOM. Ни у одного нет `data-tutorial-id`.

**Варианты:**

- **A) Centered fallback** — шаг без spotlight. Текст работает как анонс фичи.
- **B)** Использовать `people-panel` как прокси-target — дублирование шага 3.
- **C)** Добавить `data-tutorial-id="contact-mode-screen"` в `ContactAnalysisModeScreen` + принять fallback для шага 4.

**Статус: критический конфликт. Рекомендуется вариант A или объединение шагов 3 и 4.**

---

## Шаг 5 — Выбирай глубину разбора

**Та же проблема, что и шаг 4.**

Сегментный контрол `Базовый | Глубокий` (`ContactAnalysisModeSegment` / `ContactHeaderModeSwitch`) не существует без выбранного контакта. Нет `data-tutorial-id`.

Дополнительно: шаги 4 и 5 объясняют **одну и ту же систему** — синастрия и режим разбора — с разных сторон. При отсутствии spotlight оба будут centered fallback. Два подряд centered fallback без подсветки выглядят слабо.

**Рекомендация: объединить шаги 4 и 5 в один.** Например: «Добавь человека → AstroBot покажет не только его карту, но и взаимодействие с тобой — выбери глубину разбора».

**Статус: критический конфликт + кандидат на слияние с шагом 4.**

---

## Шаг 6 — Бесплатные запросы и пополнение

**Две проблемы:**

1. **Нет `data-tutorial-id`** на блоке с балансом. Блок `requestsUsed / freeRemaining / requestsBalance` находится в `ProfileSheet.tsx:407–422` без атрибута.
2. **ProfileSheet закрыт** во время туториала. Блок физически не в DOM.

Дополнительно: **ошибка в тексте шага** — «пополнить их можно в разделе «Чаты»». В dev пополнение происходит через ProfileSheet / PaywallSheet, не через раздел Чаты.

**Варианты:**

- **A)** Нацелить на `nav-profile` (`data-tutorial-id="nav-profile"` — кнопка всегда видна). Текст: «остаток запросов и пополнение — в профиле».
- **B)** Добавить `data-tutorial-id="requests-balance"` в ProfileSheet + принудительное открытие листа.

**Статус: нет target + ошибка в тексте. Рекомендуется вариант A.**

---

## Шаг 7 — Войди в аккаунт и сохрани свои данные

**Проблема: кнопка внутри закрытого ProfileSheet.**

`data-tutorial-id="profile-auth"` существует (`ProfileSheet.tsx:544`), но ProfileSheet закрыт. Без принудительного `setShowProfile(true)` элемент не в DOM. Это та же механика что была в старых шагах 8–9 оригинального туториала.

Плюс по сравнению со старым туториалом: шаг 7 идёт последним — пользователь уже прошёл все остальные шаги, контекст для регистрации здесь значительно лучше.

**Варианты:**

- **A)** Принудительно открывать ProfileSheet (как в старом туториале). Работает, но sheet открывается без действия пользователя — abrupt.
- **B)** Нацелить на `nav-profile` — кнопка всегда видна. Текст: «в профиле — регистрация, история и пополнение».

**Статус: реализуемо. Выбрать между вариантом A (точный target) и B (мягче).**

## Пути реализации

### Путь минимум (без новых data-tutorial-id)

Шаги 2, 4, 5 — centered fallback без spotlight. Spotlight получат: шаг 3 (`people-panel`), шаг 6 → `nav-profile`, шаг 7 → принудительный open или `nav-profile`. Шаг 1 — нужен wrapper.

Итого изменений в коде: 1 новый wrapper div + исправление текста шага 6.

### Путь оптимум (с новыми data-tutorial-id)

Добавить 3 атрибута:
- `data-tutorial-id="composer-area"` — обёртка над слайдером + инпутом
- `data-tutorial-id="follow-up-chips"` — на `FollowUpChips` компонент (принять centered fallback)
- `data-tutorial-id="contact-mode"` — на `ContactAnalysisModeScreen` (принять centered fallback)

Объединить шаги 4 и 5 → итого 6 шагов вместо 7.

Итого изменений в коде: 3 новых атрибута + 1 wrapper + объединение шагов + исправление текста.
